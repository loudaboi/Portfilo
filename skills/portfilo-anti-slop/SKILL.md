# Portfilo Anti-Slop Decision Gate

## Authority

Read:

1. `AGENTS.md`
2. `docs/PROJECT_STATE.md`
3. `docs/DOCUMENT_STATUS.md`
4. `docs/V1_SCOPE.md`
5. the current task-specific standard/decision record.

This skill never expands approval scope.

## 1. State the decision job

Write one sentence describing what is actually being decided.

Split materially independent decisions.

## 2. Separate evidence classes

### Approved facts and constraints

Repository authority, actual implementation, founder decisions, or verified evidence.

### Reference evidence

Real products, professional practice, research, or relevant exemplars.

### Unknowns

Anything not yet established.

### Candidate choices

Only after the first three are clear.

## 3. Research before invention

For consequential public copy/design/product choices, inspect strong relevant references before recommending.

Do not generate a polished answer and then search for support.

For significant public copy:

`reference corpus -> approved claim sheet -> message architecture -> founder approval -> wording`

## 4. No invented authority

Do not invent:

- audience promises;
- cadence;
- differentiators;
- outcomes;
- missions;
- client results;
- recurring formats;
- decorative motifs;
- features added only to fill a layout.

Label hypotheses as hypotheses.

## 5. Rejected work has no authority

Do not lightly paraphrase rejected copy or preserve a rejected composition under new cosmetics.

Return to approved evidence and constraints.

## 6. Generic-AI red team

Ask:

1. Could this appear unchanged on a generic agency/SaaS/media site?
2. Was the answer generated before the evidence?
3. Which claims are actually supported?
4. Was anything added because the page felt empty?
5. Is this one coherent model or feature soup?
6. Would deleting something improve it?
7. Does it follow the current Portfilo contract?

Revise if unsupported.

## 7. Implementation fidelity

Once approved, the contract is fixed until another explicit decision changes it.

Implementation may solve low-level engineering details. It may not silently add new product/design/copy decisions.

When a material decision is missing, surface the gap.

## Stop conditions

Stop rather than invent when:

- evidence is insufficient;
- current authorities conflict;
- a required asset is missing;
- a factual/public claim cannot be supported;
- approval does not cover the next consequential step.
