# Starting a Business Description Research

_Last updated: 2026-09-07_

_Status: DESCRIPTION APPROVED_

## Approved package inputs

### Headline

> **What actually makes starting a business hard?**

### Dek

> **New businesses have to make important decisions with very little information about what is working and what is not.**

### Body

Draft 8 remains founder-editor approved and is not reopened by this description gate.

The body uses weak sales as its main explanatory example. The same observable result can be consistent with different underlying problems, including price, offer, awareness, reach, or demand. Those explanations call for different responses. The story then explains how later activity can provide more clues, how an action can both affect the business and reveal more about the cause, and why misdiagnosis can waste limited resources.

## Description research basis

System-level research is recorded in:

`research/editorial-packaging/description-system-research.md`

The governing packaging standard is:

`docs/EDITORIAL_PACKAGING_STANDARD.md`

The reviewed human-edited examples showed several legitimate description/standfirst/summary jobs:

- establish the situation;
- state the reporting or explanation promise;
- define scope;
- surface a distinctive case, method, or evidence base;
- state a bounded finding;
- frame the reader's practical question.

They do not support a universal rule that the description should be a compressed version of the article's conclusion.

## Package analysis

The headline already performs the broad-question job.

The dek already gives the high-level answer: a new business must make important decisions while information about what is working remains limited.

A description that says only that `results have several causes`, `wrong responses cost money`, or `uncertainty makes decisions difficult` would mostly compress material already carried by the dek and body.

The useful missing layer is **concrete scope**.

Draft 8 has a clear explanatory device that the headline and dek intentionally leave out: weak sales.

That example can make the description specific without reducing the article to a story only about sales, provided the sentence explicitly presents weak sales as the example rather than the full subject.

## Selected description job

Primary job:

> **Surface the story's main explanatory example and show what that example is used to explain.**

This corresponds to the editorial-packaging modes:

- surface distinctive example;
- define scope.

The description should not try to carry the resource-cost conclusion, every possible cause of weak sales, or the article's closing lesson.

## Approved description

Founder-editor approved on 2026-09-07:

> **Using weak sales as the main example, this explainer shows how the same early business result can point to very different problems.**

This wording is the canonical description for the current story package unless explicitly reopened by the founder-editor.

## Why this proposal was selected

- it tells the reader what the article actually uses to explain the subject;
- `weak sales` provides concrete scope rather than abstract words alone;
- it does not duplicate the approved dek's `important decisions / very little information` wording;
- it does not attempt to compress the complete article conclusion;
- it remains accurate to Draft 8;
- it can function as visible story-card copy and as current metadata reuse without being written as SEO filler.
