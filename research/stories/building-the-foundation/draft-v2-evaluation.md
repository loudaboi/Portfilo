# C027 Draft v2 Evaluation

_Last updated: 2026-09-03_

## Result

**DIRECTION: PASS FOR USER REVIEW**

This is not a publication decision. Draft v2 remains internal and has no public story entry.

## What changed from Draft v1

Draft v1 tried to combine too many ideas into one article. Draft v2 deliberately keeps one message:

> An early project does not need to become your future. It should teach you something real about what to do next.

AI, starting from nothing, habits, network-building, reputation, and a universal bottleneck model were removed as separate themes.

## Evaluation

### Message clarity: PASS

A reader should be able to state the point in one sentence after reading it.

### One-thread structure: PASS

The draft follows one progression:

- pressure to choose the `right` first project;
- why preparation cannot answer every early question;
- a real project produces feedback;
- that feedback changes the next decision;
- counterargument against endless dabbling;
- resolution.

No parallel framework is introduced halfway through.

### Reader-centered rather than founder-centered: PASS

The article contains no biography and no `I did this, I did that` sequence. The author can hold a personal Perspective byline while the reader remains the subject.

### Portfilo fit: PASS

Topic: `Building`.

Likely type: `Perspective`.

The draft concerns how real work changes what a builder knows, rather than motivational discipline, hustle, or generic self-improvement.

### Complexity: PASS

The article does not require the reader to understand AI research, startup jargon, labor-market concepts, or a multi-part conceptual model.

### Evidence burden: LOW

The current draft is primarily an argument and uses hypothetical/general examples rather than consequential external factual claims. It does not currently need a methodology section or a C009-style citation density.

### Originality: QUALIFY

The underlying idea overlaps with established `learn by doing` and side-project advice. The more distinctive framing is that an early project is useful because it converts uncertainty into information that can change the next decision.

During the editorial pass, protect that framing and remove sentences that drift into generic `just start` advice.

### Risk of romanticizing failure: RESOLVED IN DRAFT

The draft explicitly states that failure is not automatically valuable and that a project must become real enough to generate consequences and feedback.

### AI relevance: DELIBERATELY EXCLUDED

Current 2026 commentary already heavily covers AI making execution easier. Adding that thread would weaken C027's clarity. It can support a separate future Perspective.

## Headline status

`Your first project does not have to be your future` is a working headline, not final.

It is clear and reader-centered but may be slightly broad. Headline audit should happen only after the argument is approved.

Louda reviews Draft v2 only for:

1. Is the message now the message he actually wants associated with the first featured Perspective?
2. Does it feel simple enough to read without having to reconstruct the thesis?
