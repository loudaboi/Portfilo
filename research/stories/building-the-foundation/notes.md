# C027 Notes

_Last updated: 2026-09-03_

## Author direction

The piece should share an idea, not narrate a personal journey.

The reader should be able to recognize their own starting position in the story. Personal experience can inform the perspective without becoming the subject.

Avoid:

- `I started from nothing`;
- a hardship montage;
- a grindset manifesto;
- a success-story frame when the author is still early;
- advice delivered as if the author has already solved the path;
- founder-personality content that makes Portfilo feel like a personal blog.

## Core conceptual model

A person can want to build something while lacking some combination of:

- knowledge;
- technical or practical skill;
- money;
- network;
- confidence from prior execution;
- reputation / trust;
- understanding of users;
- consistent habits;
- distribution;
- access to opportunities.

The article should not say these appear in a fixed order.

The model is:

```text
ambition
-> identify current constraint
-> build enough capability / leverage to cross it
-> take the next useful step
-> discover the next constraint
-> repeat
```

The foundation is cumulative even when a specific project fails: skills, judgment, relationships, habits, and evidence of execution can carry into later attempts.

## AI's role

Useful framing:

- AI can supply temporary execution capacity or accelerate access to knowledge.
- It can help a beginner attempt work that previously had a higher entry barrier.
- It can change the bottleneck from `Can I make this at all?` to `Is this worth making?`, `Can I judge the output?`, `Does anyone want it?`, or `Can I earn trust?`.
- It should not be framed as a substitute for learning, judgment, relationships, credibility, or user understanding.

Avoid absolutes:

- `Anyone can build now.`
- `Code is free.`
- `AI erased the technical barrier.`
- `Taste is all that matters.`

## Narrative approach

Open on the gap between wanting to build something and not yet having everything required to do it.

Do not open with the author.

Move from the false binary:

- either `ready`;
- or `not ready`;

into the bottleneck model.

Use concrete examples of the bottleneck moving:

- cannot prototype -> learn / use tools enough to make a first version;
- can prototype -> do not know if the problem matters -> learn from people / users;
- know the problem -> cannot execute consistently -> improve working habits / systems;
- can execute -> nobody trusts the work yet -> build a track record and relationships;
- can build -> cannot reach people -> distribution becomes the constraint.

Do not turn those examples into a universal sequence.

## Ending direction

No inspirational crescendo.

Preferred ending idea:

> You do not need to begin with everything. You need to become capable of the next useful step.

The final sentence should be earned by the argument and can be revised if it reads like a slogan.

## Working headline directions

Research question, not final headline:

`What do you build first when you want to make something meaningful but do not yet have much leverage?`

Possible headline directions for later audit:

- `What do you build when you're not ready yet?`
- `The first bottleneck is rarely the last one`
- `You don't need everything before you start building`
- `AI can shorten the distance. It cannot build the foundation for you.`

Do not lock a headline before the draft survives adversarial review.
